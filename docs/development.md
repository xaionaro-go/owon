# Development

[Quick start](../README.md) · [Runtime and API reference](reference.md)

| Package | Responsibility |
|---|---|
| `pkg/owonmodel` | Instrument values and intrinsic validation; no I/O, dialect or clocks |
| `pkg/owonscpi` | Pure HDS command compilation, supported matrices and payload interpretation |
| `pkg/owonprotocol` | Command envelopes and one bounded incremental frame decoder |
| `pkg/owonsession` | Exclusive connection lifetime, transaction leases, quarantine, recovery and cleanup |
| `pkg/owoncontrol` | Typed operation sequencing, held preflight and observation timestamps |
| `pkg/owonusb` | Physical acquisition, endpoint policy and validated native reconnection |
| `pkg/owonrpc` | Handwritten schema, wire conversions, endpoint/TLS policy; generated Go in `autogenerated` |
| `pkg/owonrpc/owonclient`, `owonserver` | Remote calls; server admission, polling, queues and a consumer-owned instrument interface |

`owond` composes USB → session → controller → RPC server. Failed startup retains
a retryable cleanup owner. RPC production code never depends on the concrete
controller, session or USB implementation. CLI/Web use the remote client; reusable
code stays in `pkg/owonctl` and `pkg/owonweb`, command packages in `cmd/owonctl/commands`.

Whole-request intrinsic validation precedes dialect support checks. Unknown enums
are invalid; recognized but unimplemented controls are unsupported. Compilation has
no side effects. The controller holds one transaction across scale preflight/writes,
state acquisition or waveform header/data reads. Failed batches stop without replay.

## Requirements

Tests need Go 1.26+, CGO, a C compiler, `pkg-config`, and libusb development
files; browser tests also need Node.js. Keep tools on `PATH` and run commands
from the checkout.

Native `owonmodel`, RPC, CLI, and web packages also support `CGO_ENABLED=0`; only the
USB backend and daemon require libusb. The package-boundary tests enforce these
production dependency directions independently of test fixture imports.

## Verification

```sh
go test ./...
go vet ./...
go test -race ./...
mkdir -p bin
go test -coverpkg=./... -coverprofile=bin/coverage.out ./...
go tool cover -func=bin/coverage.out
node --test pkg/owonweb/ui_test.js
```

The CLI integration tests build and run both command-line programs and exercise
all eight client commands against a deterministic real TCP gRPC server. These
checks require no instrument. They do not verify physical USB framing, device
recovery, or firmware behavior; perform those checks with the intended serial
and consult the hardware evidence in `docs/usb-protocol.md`.

Coverage includes native USB paths. Generated protobuf files contribute to Go's
raw totals; exclude only `*.pb.go` statement counts when reporting authored-source
coverage, and report uncovered hardware paths separately. Run race tests on a
host supported by the race runtime: a ThreadSanitizer VMA initialization failure
is an unavailable check, not a passing race result. Browser Node tests verify
interaction logic; use a real browser for layout, keyboard, and socket lifecycle
verification.

## API and regeneration

The schema is [pkg/owonrpc/owon.proto](../pkg/owonrpc/owon.proto). Generated Go files
are produced with `protoc`, `protoc-gen-go`, and `protoc-gen-go-grpc` on `PATH`.
Match the generators to the versions recorded in the generated file headers.
The well-known protobuf schemas come from the `imports/protobuf` Git submodule,
pinned to protobuf `v27.3` commit
`7cc670c1809e704ebeba90fb430d50e009f36727`. Initialize it, then regenerate:

```sh
git submodule update --init --recursive
protoc \
  -I. \
  -Iimports/protobuf/src \
  --go_out=. \
  --go_opt=module=github.com/xaionaro-go/owon \
  --go-grpc_out=. \
  --go-grpc_opt=module=github.com/xaionaro-go/owon \
  pkg/owonrpc/owon.proto
```
